# ছায়া বাড়ি: Android & iOS app

The customer app, built with React Native and [Expo](https://expo.dev) (SDK 58,
Expo Router). It talks to the same API as the website. Design, language and
business rules follow the rest of the project: see `../CLAUDE.md`, `../design.md`
and the vault node [`mobile-app`](../vault/nodes/mobile-app.md).

**This version:** menu by category, dish details, cart, Google sign-in, and
language / theme / palette settings. Checkout opens the website for now. Push
notifications, in-app checkout, orders and tracking come next.

## Layout

```
mobile/
  app.config.ts         app name, ids, icons, splash, plugins (no ios/ or android/ committed)
  eas.json              cloud build profiles: development, preview (APK), production
  .env.example          API / website URLs and Google client ids
  assets/               icons + splash, generated from the brand logo (npm run icons)
  scripts/make-icons.py
  src/app/              screens (Expo Router): (tabs)/index · cart · account, product/[id]
  src/lib/              api, auth (native Google), cart, i18n, storage
  src/theme/            palettes.gen.ts (GENERATED) + theme provider
  src/components/       glass UI pieces, product card
```

`src/theme/palettes.gen.ts` is generated by `cd ../client && npm run palettes`
from the same palette data as the website. Never edit it, and never hard-code a
colour (`npm run check:design` fails on one).

## Set up

```bash
cd mobile
npm install
cp .env.example .env.local   # then fill it in
```

| Variable | What |
|---|---|
| `EXPO_PUBLIC_API_URL` | API base with `/api`. Unset in development: `http://10.0.2.2:4000/api` on the Android emulator, `http://localhost:4000/api` elsewhere. On a real phone use your computer's LAN IP. |
| `EXPO_PUBLIC_WEB_URL` | Website address, for "order on the website" and relative product photos. |
| `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` | The **web** OAuth client id: the same value as `GOOGLE_CLIENT_ID` on the server. Without it sign-in is hidden. |
| `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` | The **iOS** OAuth client id. Also add it to the server's `GOOGLE_EXTRA_CLIENT_IDS`. |

No CORS change is needed on the server: native apps send no browser `Origin`.

### Google sign-in (one-time, in Google Cloud Console)

Google does not allow its sign-in inside an app's web view, so the app uses the
native Google SDK and sends the ID token to the existing `POST /api/auth/google`.
In the **same** Google Cloud project as the website's OAuth client:

1. **Android:** create an OAuth client of type *Android*, package `com.chayabari.app`,
   with the SHA-1 of each signing key: the EAS key (`npx eas-cli credentials`, Android)
   and, after the first Play upload, the *App signing key* SHA-1 from Play Console →
   Setup → App integrity. No id goes in the app; the web client id is enough.
2. **iOS (later, needs the Apple account):** create an OAuth client of type *iOS*,
   bundle id `com.chayabari.app`. Put its id in `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`
   and in the server's `GOOGLE_EXTRA_CLIENT_IDS`. `app.config.ts` adds the
   reversed id as a URL scheme automatically.

## Run it

The app uses native code (Google sign-in), so it runs in a **development build**,
not Expo Go.

```bash
npx eas-cli@latest login
npx eas-cli@latest init                                  # links the project to your Expo account
npx eas-cli@latest build --profile development --platform android
```

Install the APK it gives you on a phone or emulator, then start the bundler with
`npm start` and open the app. With Android Studio installed you can build locally
instead with `npm run android` (and `npm run ios` on a Mac with Xcode).

## Build for the stores

```bash
npm run build:android:preview   # installable APK to share for testing
npm run build:android           # signed .aab for Google Play (version code auto-increments)
npm run build:ios               # needs an Apple Developer account; builds on Expo's Macs
```

Set the production `EXPO_PUBLIC_*` values as EAS environment variables (expo.dev →
project → Environment variables) so cloud builds pick them up. Upload the `.aab` to
Play Console (internal testing first), or use `npx eas-cli@latest submit -p android`.

**What you need:** a Google Play Console account (have it), an Expo account (free),
and for iOS an Apple Developer account ($99/year). No Mac is needed: EAS builds iOS
in the cloud.
