Native Android and iOS apps for customers, built with React Native and Expo
in `mobile/` (Expo Router, file-based screens in `mobile/src/app`). The first
version covers the customer core: menu by category, dish details, a device
cart, native Google sign-in, and language, theme and palette settings. Checkout
links to the website for now. Admin and kitchen keep using the website. Builds
run on Expo's EAS Build in the cloud, so no Mac or Android SDK is needed.

## Rules
- **R-APP-001** [must] The app uses the same REST API as the website and never computes a price the server trusts. Totals in the app are previews (R-PLT-004).
- **R-APP-002** [must] No colour is hard-coded in `mobile/src`. Colours come only from `mobile/src/theme/palettes.gen.ts`, which `cd client && npm run palettes` generates from `palettes.mjs` and `tokens.css`. Never edit it by hand. `cd mobile && npm run check:design` must pass.
- **R-APP-003** [must] Every user-visible string in the app is bilingual, `t('বাংলা', 'English')`, with Bangla as the default.
- **R-APP-004** [must] Sign-in in the app is Google only and uses the native Google SDK, posting its ID token to `POST /api/auth/google`. Never a Google flow inside a WebView, and never another login method (R-AUTH-001).
- **R-APP-005** [must] Without `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` the app hides sign-in, and browsing and the cart keep working (R-PLT-009).
- **R-APP-006** [must] `mobile/ios` and `mobile/android` are generated by Expo prebuild and are never committed or edited by hand. Native settings live in `mobile/app.config.ts` and config plugins.
- **R-APP-007** [must] The sign-in JWT is stored in the OS keychain/keystore (`expo-secure-store`), never in AsyncStorage.
- **R-APP-008** [should] Add native packages with `npx expo install` so versions match the Expo SDK, and keep `npx expo-doctor` clean.
- **R-APP-009** [must] Staff (ADMIN/KITCHEN) who sign in to the app are told to use the website for their work. The app has no admin or kitchen screens (R-ACL-003 still decides access on the server).

## Decisions
- **D-APP-001** [confirmed 2026-10-21] Build the apps with React Native + Expo, not Capacitor or a PWA.
  Why: the owner's choice. The agent recommended Capacitor (one codebase reusing the web UI); the owner preferred truly native screens and accepted rebuilding them.
- **D-APP-002** [confirmed 2026-10-21] Sign in with the native Google sign-in SDK (`@react-native-google-signin/google-signin`). The ID token goes to the existing `POST /api/auth/google`, and the server also accepts the iOS client id as an audience (`GOOGLE_EXTRA_CLIENT_IDS`, see R-AUTH-008).
  Why: Google blocks its sign-in inside embedded WebViews; a native SDK keeps sign-in Google only with no new endpoint.
- **D-APP-003** [confirmed 2026-10-21] Phone push in the app (FCM for Android, APNs for iOS) is phase 2. The first version has no push.
  Why: it needs a Firebase project and a new server sender; the owner chose to ship the app first.
- **D-APP-004** [confirmed 2026-10-21] The first version covers the customer core: Expo scaffold, Google sign-in, glass theme and Bangla/English, menu by category, dish details and the cart. Checkout, my orders, `/track` deep links and the wallet follow in later PRs. Admin and kitchen stay on the website.
  Why: the owner picked the smallest useful first release.
- **D-APP-005** [confirmed 2026-10-21] Build with Expo EAS Build in the cloud (`mobile/eas.json`: development, preview APK, production). The owner has a Google Play Console account; there is no Apple Developer account or Mac yet.
  Why: no Mac and no Android SDK on the owner's machine; EAS builds both platforms remotely.
- **D-APP-006** [proposed 2026-10-21] App id `com.chayabari.app` on both stores, display name `ছায়া বাড়ি`, deep-link scheme `chayabari`. The app id cannot change after the first store upload.
- **D-APP-007** [proposed 2026-10-21] `palettes.mjs` also writes `mobile/src/theme/palettes.gen.ts` (every palette's light/dark tokens plus the neutral and status colours parsed from `tokens.css`), and `check-colors.mjs --mobile` guards `mobile/src`. One palette source for web and app.
- **D-APP-008** [proposed 2026-10-21] Random palette mode is the app default too (R-DSN-016) and keeps the website's 30 s to 5 min hold, but the app only swaps when it starts or returns to the foreground, never while a screen is in view.
- **D-APP-009** [proposed 2026-10-21] Until in-app checkout ships, the cart screen shows the subtotal preview and a button that opens the website to order. The app cart is not carried over to the website.
- **D-APP-010** [proposed 2026-10-21] The app uses the phone's system fonts for now. The website's fonts are woff2 subsets that React Native cannot load; bundling TTFs of Hind Siliguri and Anek Bangla is a follow-up (I-APP-003).
- **D-APP-011** [proposed 2026-10-21] Native icons come from `expo-symbols` (SF Symbols on iOS, Material Symbols on Android) rather than an icon font package.

## Open questions
- **Q-APP-001** [open 2026-10-21] What are the live website and API addresses for production builds? They set `EXPO_PUBLIC_API_URL` / `EXPO_PUBLIC_WEB_URL`, and https App Links / Universal Links for `/track/<token>` need the domain plus the Play signing SHA-256 (and later the Apple Team ID) in `/.well-known` files.
  Options: (a) set them as EAS environment variables once known (recommended) · (b) hard-code them in `app.config.ts`
- **Q-APP-002** [open 2026-10-21] When will the Apple Developer account ($99/yr) be created? iOS builds, TestFlight and the iOS OAuth client wait on it.
  Options: (a) after the Android app is live on Play (recommended) · (b) now, to launch both together
